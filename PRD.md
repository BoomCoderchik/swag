# PRD — Swag AI | Халявные нейросети

> Статус: v0.2 · Дата: 2026-08-25 · Владелец: @user
> Канал: **Swag AI | Халявные нейросети** · Стек: **Python 3.12 + aiogram**
> Референс формата: канал **neuralBox** (GitHub AI Radar).

---

## 1. Проблема

Бесплатные раздачи в мире ИИ (временный бесплатный доступ к платным моделям, промокоды,
free-tier запуски вроде «Ox Alpha Free», открытые исходники с ограниченным окном использования)
появляются ежедневно, но разбросаны по десяткам источников: GitHub, RSS-блоги, Telegram-каналы,
Hacker News, Product Hunt. Пользователь физически не успевает их отслеживать.

**Решение:** автоматизированный Telegram-канал, который сам находит, фильтрует и публикует
такие раздачи в едином визуальном формате: карточка-картинка + краткое описание на русском +
ссылка + хэштеги.

## 2. Цели и метрики

| Цель | Метрика | Целевое значение (3 мес) |
|---|---|---|
| Автоматическая публикация без ручного труда | % постов, опубликованных без правки | ≥ 90% |
| Свежесть | Задержка между появлением раздачи и постом | ≤ 2–6 часов |
| Отсутствие дублей | Повторные посты одного и того же | 0 |
| Рост канала | Подписчики | 500+ |
| Вовлечённость | Переходы по ссылкам (CTR) | отслеживаем через t.me/preview + UTM |

## 3. Целевая аудитория

- Пользователи нейросетей, желающие экономить (студенты, разработчики, энтузиасты).
- Подписчики каналов типа neuralBox, «халявных» каналов, AI-дайджестов.

## 4. Формат поста (по референсу neuralBox)

1. **Карточка-изображение** (тёмная тема): логотип канала, заголовок (название инструмента/репо),
   краткое описание на русском, строка статистики (⭐ stars · 🍴 forks · язык / «FREE до 01.09»),
   топики/теги, URL источника.
2. **Подпись к фото** (caption ≤ 1024 символов — жёсткий лимит Bot API):
   - Заголовок-ссылка на источник
   - 2–4 предложения описания на русском (генерирует LLM из английского описания)
   - Строка метрик: `⭐ 149 · 🍴 11 · Python` или `🎁 FREE до 01.09`
   - Инлайн-кнопки: «Открыть на GitHub» / «Страница канала»
   - Хэштеги: `#github #ai #opensource #ai_agents ...` (автогенерация из топиков)

## 5. Функциональные требования (MVP)

| ID | Требование | Приоритет |
|---|---|---|
| F1 | Сбор из источников по расписанию (интервал настраивается, 15–60 мин) | P0 |
| F2 | Источники: RSS официальных блогов AI-лабораторий (OpenAI, DeepMind, Anthropic, Mistral, Meta, Qwen) | P0 |
| F3 | Источники: RSS AI-СМИ (TechCrunch, VentureBeat, Ars Technica, The Verge) + «free»-ленты агрегаторов (HN, Reddit) | P0 |
| F4 | Дедупликация: SQLite, ключ = URL; повторно не постить | P0 |
| F5 | Свежесть: постить только новости младше FRESH_HOURS (по умолч. 48 ч) | P0 |
| F6 | Релевантность: только новости про бесплатное (free tier, кредиты, промокоды, раздачи, выход free/open-source моделей) — ключевой фильтр + LLM-скоринг (Gemini Flash) | P0 |
| F7 | Публикация в канал: текстовый пост с ссылкой (Фаза 1), карточка-изображение + кнопки (Фаза 2) | P0 |
| F8 | Антифлуд: максимум MAX_POSTS_PER_CYCLE постов за цикл, пауза между постами | P0 |
| F9 | Конфигурация через `.env` + `sources.yaml` (без правки кода) | P0 |
| F10 | Логирование и обработка ошибок (пропущенный источник не роняет цикл) | P0 |

> Решение от 25.08.2026: GitHub-репозитории как источник убраны — в канале публикуются
> только новости о бесплатном, а не ссылки на инструменты.

## 6. Нефункциональные требования

- **Режим 24/7** — хостинг с постоянным процессом (не Vercel, см. `docs/research.md`).
- **Лимиты Telegram**: caption ≤ 1024 симв.; фото ≤ 10 MB; ≤ ~20 сообщ/мин в один канал.
- **Лимиты Gemini free tier**: ~10–15 RPM / ~1500 RPD — при 20–50 постах/день запас большой.
- **Лимиты GitHub API**: 60 req/час без токена, 5000 с токеном → использовать токен.
- **Отказоустойчивость**: retry с backoff; при недоступности LLM — публикация без саммари
  (fallback на машинное описание из источника).
- **Секреты** только в `.env`, не в репозитории.

## 7. Вне скоупа MVP (backlog)

- Чтение чужих Telegram-каналов (Telethon userbot — риск бана аккаунта, отложить).
- Веб-панель модерации постов (режим «черновик → approve → publish»).
- Комментарии/реакции, реферальная система, монетизация (реклама).
- Мультиязычность, несколько каналов с разных аккаунтов.

## 8. Архитектура (кратко)

```
[Scheduler APScheduler, каждые N мин]
        │
        ▼
[Fetchers: github.py, rss.py, ...]  ← sources.yaml
        │
        ▼
[Dedup: SQLite (posts: url_hash UNIQUE)]
        │  только новые
        ▼
[Enricher: Gemini Flash → русское описание, теги, скоринг «халявности»]
        │
        ▼
[Renderer: HTML-шаблон → PNG (Playwright) или Pillow]
        │
        ▼
[Publisher: aiogram sendPhoto + caption + inline-кнопки → канал]
```

Подробно: `docs/architecture.md`. Ресерч с источниками: `docs/research.md`.

## 9. Хостинг (решение от 25.08.2026)

Задача: бесплатно, открыто, без регистраций на облачных платформах. Полный разбор — `docs/research.md`.

| Вариант | Free в 2026 | Пригодность |
|---|---|---|
| **GitHub Actions cron** | безлимит для **публичных** репо; в приватных на free-аккаунте schedule **отключён**; реальные задержки запусков (заявлено 2/час → реально 1–2/час) | ✅ **выбрано**: workflow `--once` по расписанию, состояние — коммит SQLite в репо |
| Oracle Cloud Always Free | VM навсегда (с 18.08.2026 — 2 OCPU / 12 GB) | ❌ отклонено: нужна регистрация с картой |
| Render free | 750 ч/мес, засыпает через 15 мин | ❌ не для 24/7 |
| Koyeb free | 1 сервис, scale-to-zero после 1 ч без трафика | ❌ |
| Railway / Fly.io | free tier убраны, ~$5/3.3 в мес | ⚠️ если появится бюджет |
| Свой ПК + Docker | бесплатно | ✅ для разработки |

**Решение:** GitHub Actions cron в публичном репо (`.github/workflows/parser.yml`):
запуск `python -m swag --once` 2 раза в час, секреты в repo secrets,
дедуп-база `state/swag.db` коммитится обратно. Задержки запусков некритичны —
пайплайн идемпотентен.

## 10. Этапы (roadmap)

- **Фаза 0 — каркас**: PRD, архитектура, конфиги. ✅
- **Фаза 1 — консольный парсер** (в работе): GitHub + RSS → дедуп → публикация в канал (текстовый пост, DRY_RUN).
- **Фаза 2 — LLM + карточка**: русские описания, рендер изображения, полный формат поста.
- **Фаза 3 — прод**: деплой 24/7, мониторинг ошибок, автоперезапуск.
- **Фаза 4 — рост**: доп. источники, скоринг качества, отложенный постинг по часам пик.
